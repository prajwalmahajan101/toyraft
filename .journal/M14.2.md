## Goals

Close the six findings toymq v3 M1 surfaced against v1.0.0-rc.2 (single-node
embedded `toymq --replicate`), two release-blocking, and ship v1.0.0-rc.3. A
post-v1.0.0-rc.2 decimal follow-up to Phase 14, driven by dogfooding (precedent:
`M14.1.md`), not the ROADMAP. The dogfood gate stays open for toymq v3 M2
(multi-node kill-leader + partition-heal linearizability, which depends on B1).

## What shipped

Blockers (gating regression tests):

- **B1 — restarted leader could not write.** `pkg/raft/node.go` `newNode` now
  restores the in-memory `Log` from `Storage` (`FirstIndex..LastIndex`) before
  `started=true`. Previously it built an empty `&Log{}` and loaded only
  HardState, so `LastLogIndex` read 0 while `CommitIndex` recovered; the next
  `Propose` appended over the persisted range, `Storage.Append` rejected it, and
  `proposeLocked` returned `ErrProposalDropped`. Test
  `TestRestartRestoresLogAndAcceptsWrites`.
- **B2 — restart replayed the whole log through `Apply` (double-apply; violated
  API-05).** Durable applied checkpoint via `Snapshot`/`Restore` (ADR-0024):
  `raft.Snapshot{Index,Term,Data}` + `Storage.SaveSnapshot`/`LoadSnapshot`
  (`pkg/storage` + the `pkg/raft.Storage` subset; file impl atomic
  tmp+rename+SyncDir, CRC32-C; memory impl); `pkg/kvsm` tracks its applied index
  and implements `Snapshot`/`Restore`; the driver checkpoints every
  `Config.SnapshotInterval` (default 1024) applied entries and on clean `Stop`,
  and `New` restores the SM and resumes `Apply` from `snapshot.Index+1`. A clean
  restart replays nothing. Test `TestSnapshotResumeNoDoubleApply` +
  `TestSnapshotPeriodicCheckpoint`.

Friction:

- `Propose` returns `(Index, Term, any, error)` — the Apply result (BREAKING,
  pre-1.0). Test `TestProposeReturnsApplyResult`.
- `pkg/transport/inproc` `NewHub` defaults a nil `HubConfig.Clock` to the real
  clock (ADR-0023 parity) instead of hard-erroring. Test
  `TestNewHubDefaultsNilClock`.
- `pkg/transport/http` `Config.Validate` accepts an empty `PeerURLs` (self-only
  single node); self-URL still rejected. Tests `TestSelfOnlySingleNodeConfig`,
  `TestSelfURLStillRejected`.
- `docs/LLD.md` "Embedding toyraft" section (§7) + README note; LLD §2/§3
  updated for the new surface; `docs/lld-go-doc-golden.txt` regenerated.

## ADRs introduced

- ADR-0024 — Durable applied checkpoint via `Snapshot`/`Restore`; restore the
  in-memory log on restart. Snapshot is the durable applied floor; frozen
  `Snapshot()/Restore()` stubs stay `ErrSnapshotUnsupported` (STOR-01 intact).

## Decisions made (non-ADR)

- Journal filed as `M14.2.md` (decimal follow-up), mirroring `M14.1.md`.
- B2 chose full Snapshot/Restore (option b) over persist-appliedIndex-only
  (option a, regresses in-memory SMs) and an Apply replay flag (option c,
  changes the frozen Apply signature). Recorded in ADR-0024.
- No `CHANGELOG.md`: release notes ship in the annotated tag (rc.2 precedent).
- Release is the annotated `v1.0.0-rc.3` tag only (rc.2 precedent); no GitHub
  release, no GoReleaser (a library tag; `make release` publishes binaries if
  ever wanted).

## Risks retired

- **Restarted single-node leader accepts writes** — `TestRestartRestoresLog…`.
- **No replay double-apply on clean restart** — `TestSnapshotResumeNoDoubleApply`
  asserts `Apply` is not called for indices ≤ the checkpoint.
- **Single-node external embed** — both transports build with a zero-value clock;
  http accepts empty `PeerURLs`.

## What surprised us

The two SM types pull opposite ways on restart: an in-memory SM (`kvsm`) needs
replay to rebuild, a durable SM (toymq's WAL) must not re-apply. Neither
persist-appliedIndex-alone nor replay-with-a-flag serves both without changing
frozen surface; snapshots are the one mechanism that does. Also: the new
fake-clock propose test helpers busy-advanced the clock without yielding, which
passed on multi-core dev boxes but starved the driver goroutine on a single-CPU
CI runner — reproduced with `GOMAXPROCS=1`, fixed with a 1ms per-advance yield
(the pattern the existing `advanceUntil` already used).

## Follow-ups

- [x] Tag `v1.0.0-rc.3` after merge (plain semver library tag).
- [ ] Downstream toymq: bump `require ... v1.0.0-rc.3`; drop the app-level
      applied-index marker workaround (the node now owns the checkpoint).
- [ ] v2: log compaction below the snapshot horizon (`FirstIndex` still 1); the
      frozen `Snapshot()/Restore()` stubs remain reserved for that contract.
- [ ] A crash between checkpoints replays `(lastSnapshot, commit]`; if an
      embedder wants zero-replay-after-crash, tune `SnapshotInterval` down.

## Seeds for next phase

- toymq v3 M2 (multi-node) is unblocked by B1; linearizability there depends on
  the restart-write fix landing here.
- `SnapshotInterval` default (1024) is untuned — a real embedder's workload
  should calibrate it against its Apply-side durability cost.
