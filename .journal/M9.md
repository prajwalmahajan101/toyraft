## Goals

Ship the second `raft.Transport` implementation — HTTP/JSON — so a ToyRaft
cluster can run across real processes and hosts, and prove it against the SAME
impl-agnostic conformance suite the inproc Hub satisfies:

> a stdlib-only HTTP transport whose byte-exact wire contract, per-peer backoff,
> and leader-hint redirect are all verified behaviourally, with the inproc Hub
> reconciled to the frozen push interface so both share one conformance suite.

## ADRs introduced

- **ADR-0014 — inproc transport reconciliation (additive Hub.Transport
  wrapper).** Ratifies wrapping `Connect(id)`'s `*Endpoint` in an additive
  `raft.Transport` adapter rather than changing the load-bearing pull API, and
  names both frozen-doc drifts (LLD §6 `Connect` signature; TRAN-06/SC6 wording)
  as advisory/superseded.
- **ADR-0015 — HTTP transport owns its peer-URL address book.** The Raft core
  (`raft.Config.Peers []NodeID`) carries no NodeID→address map; the http
  transport owns the resolution table in its own `http.Config`, keeping the core
  URL-agnostic. `raft.Config` is NOT extended.

## Decisions made (non-ADR)

- **DTO vs tagged Message.** The JSON wire projection lives in a dedicated
  `wireMessage` DTO (`wire.go`) so the frozen `raft.Message` stays tag-free
  (ADR-0015). `Entry.Data` uses the `encoding/json` default (standard base64) —
  deliberately not customized.
- **SC3 backoff layers INSIDE a single `Send`.** The retry loop is entirely
  intra-`Send`; it is invisible to the Raft core, whose heartbeat remains the
  cross-tick retry. This preserves the frozen `raft.Transport` "best-effort;
  returning an error does NOT cause Raft to retry" contract verbatim. Transient
  classification is uniform (5xx OR any net-level error → retry; 4xx →
  terminal); all backoff timing routes through `cfg.Clock`, the sole sanctioned
  wall-clock use being `context.WithTimeout` for the per-request deadline.
- **Disconnect = pump-stop (inproc).** `hubTransport.Close` cancels only that
  node's inbound pump; the Hub and other nodes keep running — mirroring HTTP's
  Close-stops-listener-but-process-persists shape, which is what SC6 requires.
- **SC4 peer-RPC scope only.** The `X-Raft-Leader-Hint` redirect is emitted for
  peer RPCs (Node.Step returning `*raft.ErrNotLeader`); the client-facing KV
  redirect is deferred to Phase 10's reference demo.
- **check-no-time-now TARGETS extended.** `pkg/transport/http` is now scanned
  (RESEARCH Open Q4 / Pitfall 1) so a future `time.Now()` leak in the new
  package cannot hide. One doc-comment reword in `doc.go` was needed because the
  grep-based check matches the literal `time.Now()` token even in prose.

## What surprised us

- **The lint gate (QUAL-01) is still blocked, and it is a config-schema /
  CI-versioning decision, not a code fix.** The installed `golangci-lint`
  v2.12.2 refuses the repo's `.golangci.yml` with `unsupported version of the
  configuration: ""` — the config is written to the **v1** schema (no
  `version: "2"` key), which is deliberate: `.golangci.yml` is pinned to the v1
  binary that CI's `golangci-lint-action` builds from source (documented in
  ADR-0003 and in the config header since ~06-06). Migrating the file to the v2
  schema would fix the local binary but risks breaking CI's pinned toolchain, so
  it is out of scope for a phase-execution plan — it belongs to an ADR-0003
  update (flagged for Phase 14). **In lieu of golangci-lint**, this phase relies
  on `go vet ./...` (clean, including the Go 1.25 `waitgroup` analyzer) plus
  manual application of the actionable style findings coordinators relayed
  (`minmax`/`rangeint` tidied in `client.go` across 09-04/09-05; `rangeint` in
  `conformance_test.go`). The `waitgroupgo` finding at `server.go:97` is a
  confirmed false positive (canonical `wg.Add(1)`; `go func(){ defer wg.Done()
  … }` pattern; `go vet` clean). **Human decision owed:** update ADR-0003 +
  migrate `.golangci.yml` to schema v2 (Phase 14) so the lint gate runs locally
  again.
- **`Start()` returns before the listener binds.** `http.Server.ListenAndServe`
  runs in the tracked goroutine, so `New` returns before the socket is
  accepting. The conformance factory adds a bounded `waitListening` TCP-dial
  readiness gate before the suite's first `Send` — a real-clock ceiling
  (loopback comes up in single-digit ms), mirroring the suite's own bounded-wait
  discipline, not a logical timer.
