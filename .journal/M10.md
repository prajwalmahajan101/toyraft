## Goals

Wire the whole stack — the `raft.Node` library (Phase 7), file storage (Phase 8),
and the HTTP transport (Phase 9) — into a runnable cluster a reader can `make demo`
and watch reach consensus:

> a reference KV state machine + a `toyraftd` daemon + a `toyraftctl` CLI, driven
> by a single `make demo` that boots an N-node cluster, proves a write/read
> round-trip, partitions the leader, re-elects, heals, and converges — all over
> real HTTP processes, with the frozen core untouched.

## ADRs introduced

- **ADR-0016 — reference demo daemon: two-listener model + non-blocking peer
  sends.** Ratifies (1) the two-listener model keeping the frozen Phase 9
  transport server untouched while a second daemon-owned server carries the KV
  API; (2) the `clientPort = peerPort + 2000` convention and the three address
  books built from one `-peers` flag; (3) leader-only reads (`GET /kv` reads
  `kvsm.Get` on the leader, followers 307-redirect) — not linearizable, accepted
  for a v1 demo; (4) the client API on `http.DefaultServeMux` for free
  pprof/expvar; and (5) the non-blocking async-transport decorator +
  tightened timeouts living in `cmd/toyraftd`, so the demo owns its liveness
  tuning and the core stays policy-free.

## Decisions made (non-ADR)

- **Reads are leader-only-read via `kvsm.Get`.** `Node.Propose` returns
  `(Index, Term, error)` and discards the Apply result, so a write is
  `Propose(op)` → `200`; a read bypasses the log and reads the map directly on
  the leader. Not linearizable (no read-index), documented as a v1 limitation.
- **`kvsm` is NOT covered by `check-lld-drift`.** The gate scopes `pkg/raft`,
  `pkg/storage`, `pkg/storage/storagetest`, `pkg/transport/inproc` only; the
  golden was left untouched.
- **DELETE carries a nil body** in `toyraftctl` — nothing to replay across the
  307, method preservation alone suffices; only PUT needs `GetBody`.
- **Step-down is verified as "no longer reports role==leader".** A demoted
  node's `/status` 307-redirects, so a direct read against it yields empty, not
  `follower`; rejoin/convergence is proven via the redirect-safe
  `toyraftctl get k2` read instead. The `k2` write targets a live SURVIVOR (not
  the first node seen as leader) so post-election churn doesn't strand it.

## What surprised us

- **A synchronous `Transport.Send` to a frozen peer stalls the tick loop and
  churns elections — fixed in the DEMO layer, not the frozen core.** The Phase 7
  driver calls `Send` synchronously inside the tick loop. Under the SC5 partition
  (`kill -STOP` the leader), a synchronous `Send` to that node blocks the whole
  tick up to `SendTimeout`. At N=5 this desynchronised heartbeats badly enough
  that the cluster churned terms (11→22→34) without settling — the SC5 gate was
  unreachable. Fix: `cmd/toyraftd/asynctransport.go` wraps the HTTP transport in
  a non-blocking `raft.Transport` decorator (per-peer buffered queue + drain
  goroutine; `Send` enqueues and returns immediately, a full queue DROPS and the
  next heartbeat is the retry — exactly the loss the best-effort `Send` contract
  already tolerates), plus `SendTimeout` tightened 1s→150ms and `MaxAttempts`
  3→1. Crucially this lives entirely in `cmd/toyraftd`: `pkg/raft` and
  `pkg/transport/http` stay byte-identical (`make lld-drift` OK,
  `go test -race ./pkg/raft/...` green). The demo owns its liveness tuning; the
  core stays policy-free.
- **`http.DefaultServeMux` gives pprof + expvar for free.** Serving the KV API
  on `DefaultServeMux` means the blank `_ net/http/pprof` and `_ expvar` imports
  register `/debug/pprof/*` and `/debug/vars` with zero extra wiring. Fine for a
  single demo binary; a library consumer would use a private mux (noted in
  ADR-0016 consequences).
