## Goals

Commit the upfront design, contract, and process documents that govern every
subsequent phase, in the public repo, **before any consensus code begins** —
matching the toykv/toymq house style. After this phase:

- no architecture decision is allowed without an ADR (PROC-01/PROC-06),
- no phase completes without a journal entry (PROC-02, this file's own genre),
- no substantive proposal merges without an RFC (PROC-03),
- the LLD is the byte-for-byte source of truth for the public API surface, so
  consumer projects (toykv-cluster / toymq-cluster) can be designed in parallel.

Requirements covered: DOC-01..DOC-15, PROC-04, PROC-05.

## ADRs introduced

- **ADR-0000** — Record architecture decisions — the meta-ADR establishing the
  Michael Nygård practice: every architecture decision lands a numbered ADR
  under `docs/adr/`, drafted via the `architecture-decision-records` skill.

(No implementation ADRs land in Phase 1 — there is no consensus code yet. The
first *decision* ADRs begin in Phase 1.1 / Phase 2. ADR-0005, cited below in
"Seeds", is the first Phase-driven decision, landing in Phase 3.)

## Decisions made (non-ADR)

- **ADR numbering starts at 0000 (meta) and the first decision ADR is 0002+.**
  ADR-0001 was never assigned — a permanent hole in the sequence. The gap is not
  filled by renumbering (that would break cross-references). This is documented
  in `docs/adr/INDEX.md` (backfilled Phase 14).
- **`.planning/` is git-local.** STATE.md and per-plan SUMMARY files are working
  artifacts; the public record is commits, PRs, ADRs, RFCs, and these journals.
- **The LLD is the byte-for-byte source of truth (Working Agreement 4).** Any
  code that changes a public interface must ship the LLD amendment in the same
  atomic commit. This is what makes the later `check-lld-drift` golden gate
  meaningful.

## Risks retired

- **Implementation drift from intent** — every public type is pinned in
  `docs/LLD.md` before any code, and the drift golden (from Phase 2 on) enforces
  it.
- **Scope creep** — non-goals are locked in `docs/PRD.md` and
  `docs/rfc/0001-v1-scope-and-non-goals.md`; adding a scope item requires an RFC.
- **P0/P1 prevention baked into specs before code** — `docs/CONCURRENCY.md`
  (single-mutex, lock order) and `docs/WIRE.md` (307-redirect, leader hint)
  design out whole classes of bugs before implementation.
- **Consumer-integration risk** — the LLD locks the SDK surface so
  toykv-cluster / toymq-cluster can be designed in parallel; `docs/SECURITY.md`
  §3 pins the per-message-`fsync` / cluster-durability composition contract.
- **Process-rot risk** — ADR/RFC/journal templates + the PR template + skill
  bindings enforce the discipline from day one.

## What surprised us

- **Writing the durability contract before the storage code paid off.**
  `docs/SECURITY.md` §3 had to spell out that a write is durable to the cluster
  only once a *quorum* has `fsync`ed (not just the leader), and that consumers
  must not ack before `StateMachine.Apply` — a distinction that would later bite
  as the `HardState.Commit`-must-persist trap in Phase 8. Pinning it in prose
  first meant the storage phase had a spec to check against, not a guess.
- **The snapshot forward-compat policy needed deciding at spec time, not impl
  time.** The LLD had to commit to `Snapshot`/`Restore` existing on the frozen
  interfaces (returning `ErrSnapshotUnsupported` in v1) so Phase 3's storage
  freeze (ADR-0005) had a shape to satisfy — even though no snapshot code would
  ship in v1. Deferring the *decision* would have forced a breaking interface
  change later.
