## Goals

Unblock external consumers of `pkg/transport/http`. A post-v1.0.0-rc.1 decimal
follow-up to Phase 14 (precedent: `M1.1.md`), driven by dogfooding rather than the
ROADMAP: make the HTTP transport constructible from outside the module and ship it
as v1.0.0-rc.2.

## What shipped

- `pkg/transport/http/config.go` — added `func (c *Config) applyDefaults()` that
  defaults a nil `Clock` to `clock.NewReal()`; rewrote the `Clock` field doc from
  "MUST be non-nil" to "Optional; a nil Clock defaults to the real clock in New".
- `pkg/transport/http/transport.go` — `New` now calls `cfg.applyDefaults()` before
  `cfg.Validate()`; updated `New`'s doc comment.
- `pkg/transport/http/nil_clock_test.go` — `TestNewDefaultsNilClock`: two-node pair
  built with `Clock` unset, exercised with a real A→B Send/receive round-trip under
  the package goleak `TestMain`.
- `docs/adr/0023-http-transport-defaults-nil-clock.md` (+ `INDEX.md`).
- `docs/lld-go-doc-golden.txt` — regenerated for the `Clock`/`New` doc-comment drift.

## ADRs introduced

- ADR-0023 — Default a nil HTTP-transport Clock to the real clock in New — parity
  with `raft.Config.applyDefaults`; non-breaking, more-permissive.

## Decisions made (non-ADR)

- Journal filed as `M14.1.md` (decimal follow-up), not a new phase — this is a
  targeted hotfix on top of the closed Phase 14, mirroring the `M1.1.md` precedent.
- `Validate()`'s nil-Clock branch kept as-is; now unreachable via `New` but retained
  as a guard for direct `Validate` callers.

## Risks retired

- **External constructibility of `pkg/transport/http`** — confirmed by
  `TestNewDefaultsNilClock`, which builds the transport exactly as an external caller
  must (no `internal/clock` reference) and drives a live round-trip.

## What surprised us

The root cause was pure API ergonomics, not logic: the transport's real usage is a
single `Clock.After()` call, fully served by the real clock. The blocker was that the
one input an external caller *cannot* name (`internal/clock.Clock`) was mandatory.
`pkg/raft` had already dodged this exact trap with `applyDefaults` months earlier — the
transport simply never inherited the pattern.

## Seeds for next phase

- The `internal/clock` → public-clock question is the last real external-ergonomics gap;
  if v1.1 opens, ADR-0023's rejected alternative is the starting point.

  the constructor (the `applyDefaults` pattern) rather than mandate it in `Validate`.
