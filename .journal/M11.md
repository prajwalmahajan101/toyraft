## Goals

Give ToyRaft a chaos suite that exercises the cluster under adversarial
conditions and asserts *real progress*, not the absence of panics:

> a seeded in-process failure matrix (reorder / duplicate / drop / delay /
> partition, all five knobs combinable and byte-deterministic from one seed),
> plus a real process-kill harness that terminates a leader's whole OS process
> group and proves re-election + write survival + a durable-commit oracle — both
> halves dumping a shared history the Phase-12 linearizability checker will
> consume, and both wired into CI as a terminal (no-retry) gate.

## ADRs introduced

Two ADRs this phase (PROC-01/06):

- **ADR-0017 — synchronous delivery-drain seam for byte-deterministic chaos
  traces.** The determinism fix that unblocked SC1. `raftest.Cluster.Tick`'s
  between-pass `deliveryQuiesce()` was a literal `time.Sleep(2ms)` waiting on the
  async Hub dispatcher goroutine, so *which* Tick observed a delivery depended on
  wall-clock jitter and the committed set diverged run-to-run under chaos. The fix
  adds `HubConfig.SyncDelivery` + `Hub.DrainDueSync` — a goroutine-free in-line
  drain reusing the async dispatcher's `drainDueLocked` + `orderLocked` verbatim —
  and routes the harness through it; the async path stays the default and is
  untouched. This was an **approved Rule-4 architectural deviation** raised by the
  first 11-01 executor (user approved Option A: fix the harness determinism). It
  also removed the last `time.Sleep` from `cluster.go`, clearing the standing
  `check-no-time-now` blocker carried since 07-04.
- **ADR-0018 — chaos suite: PGID group kill, positive oracles, and the
  determinism boundary.** Ratifies (a) the negative-pgid group kill
  (`Setpgid` + `syscall.Kill(-pgid, SIGKILL)`, POSIX-gated) with `ps`
  process-absence as the primary leak gate; (b) positive oracles (≥N commits AND
  ≥M leader changes) replacing "no errors raised"; (c) the inproc-only
  byte-determinism boundary (process-kill is wall-clock by design); and (d) the
  shared `HistoryEvent` recorder feeding Phase 12.

## Decisions made (non-ADR)

- **N=5 default** for the process-kill cluster (RESEARCH Open-Q1) — odd, tolerates
  two failures, cheap enough for CI.
- **BASEP=17001** for the process-kill harness (peer 17001+i / client 19001+i),
  well clear of the demo's 7001 (RESEARCH Pitfall 5) so a stray demo can't collide.
- **Chaos runs as a step in the existing `test` job**, not a new required check
  (RESEARCH Open-Q3) — keeps ADR-0002's enumerated check names and branch
  protection unchanged.
- **Process-kill recorder bound to `clock.NewReal()`** (RESEARCH Open-Q2) — the
  harness is genuinely wall-clock, so its history is non-deterministic by design;
  SC1 byte-determinism is an inproc-only property.
- **The committed oracle reads the `/status commit_index` seam on a majority of
  survivors**, not a 307-followed read-back alone (a read can be served from the
  leader's applied KVSM without a durable commit signal).

## What surprised us

- **The chaos suite's own harness was the source of non-determinism, not the
  chaos RNGs.** SC1 failed at first not because the split-seed chaos RNGs (ADR-0007)
  were wrong but because the harness's between-pass quiesce was a `time.Sleep(2ms)`
  racing the async Hub dispatcher goroutine — so *which* Tick saw a delivery
  depended on wall-clock progress, and the committed set diverged run-to-run
  (seed 42: run A committed k21 at index 3, run B committed k25). The fix
  (ADR-0017) was a synchronous drain seam, and it happened to clear the standing
  `check-no-time-now` blocker on `cluster.go` carried since 07-04.
- **"No errors raised" is a silent-failure trap.** A cluster that stops committing
  raises nothing; only the positive ≥N-commits / ≥M-leader-changes oracles catch
  it. This is the whole point of the chaos suite and it shaped both halves.
- **Process-absence, not port-free, is the reliable leak signal.** A killed
  listener's port can linger in `TIME_WAIT`, so `lsof` alone would false-positive
  on a leak; `ps -o pgid=` process-absence is the primary gate.
