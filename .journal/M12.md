## Goals

Give ToyRaft its v1 correctness gate: replay operation histories through
`github.com/anishathalye/porcupine` against a model of the reference KV state
machine and assert linearizability, including the Raft paper's Figure 7 (log
matching across leader change) and Figure 8 (the current-term commit rule).

> Build a `test/linearizability` package with a kvsm-faithful KV-register
> `porcupine.Model`, a corpus of concurrent multi-client histories, Figure 7/8
> encodings, and a fault-injection artifact — all wired into CI as a terminal
> (no-retry) gate so a single linearizability violation fails the build.

## What shipped

All new code lands under `test/linearizability/`, plus one CI step and ADR-0019.
Landed across three waves on `feature/linearizability`:

- **12-01 — KV-register model + non-vacuity proof + history-shape gate**
  (`f655b35`, `aa46b1f`, `96e2a62`).

  reproduces `pkg/kvsm` exactly — `set` = unconditional write, `del` = collapse

  model would fail the reject test). `history_shape_test.go`

## ADRs introduced

- **ADR-0019 — linearizability porcupine model + scripted histories.** Ratifies
  (a) the porcupine v1.0.3 pin as a test-only dependency (no `pkg/` leak);
  (b) the kvsm-faithful KV-register model (forbid-empty-value plain-string
  state, partition-by-key, `CheckOperationsVerbose` for visualization);
  (c) the scripted-concurrent-history corpus (Option A) over re-plumbing the
  harness for recorded multi-client histories (Option B), because the Phase-11
  single-client dumps are trivially linearizable; and (d) the safe
  crafted-illegal SC4 fault-injection pattern.

## Decisions made (non-ADR)

- **Scenario names map to interleaving flavors, not Phase-11 dumps**
  (RESEARCH Open-Q2). `steady-state` / `leader-churn` / `packet-loss` are
  authored concurrency patterns, not replays of recorded histories.
- **`porcupine.Unknown` (timeout) is treated as a test failure**, never a pass —
  for a gate, "could not certify" is not "certified". Histories are tens of ops
  so `Unknown` never occurs on a green run.
- **CI step uses `-timeout 5m`** — scripted histories are fast, so the ample
  budget is only a flake guard, not a real bound.
- **Optional real-dump smoke consumer deferred** (RESEARCH Open-Q5) — `FromHistory`
  exists as the normalization seam but is not yet wired to a chaos-dump test.

## Risks retired

Per ROADMAP "Key risks retired":

- **T-2 (no correctness oracle / vacuous gate).** Retired: `model_test.go`
  proves the model is non-vacuous (it rejects a crafted illegal history), so a
  broken Raft would fail the gate; the corpus is non-trivially concurrent.
- **T-3 (Figure 7/8 unverified).** Retired: `TestFigure7Linearizable` and
  `TestFigure8Linearizable` encode both scenarios and pass; Figure 8 hinges on
  ADR-0010 (current-term commit rule).
- **T-5 (violations invisible / undiagnosable).** Retired:
  `CheckOperationsVerbose` + `VisualizePath` emit an HTML counterexample on
  `Illegal`, proven by `TestFigure8ViolationProducesArtifact` (SC4).

v1 acceptance: ToyRaft credibly implements Raft — the Figure 7/8 histories pass
the linearizability oracle end-to-end.

## PROC-03 (RFC) — evaluated, NOT triggered

PROC-03 was evaluated and does **not** apply: the linearizability suite is
internal test infrastructure under `test/linearizability/`. It touches no public
API and no Phase-1 frozen contract — `pkg/raft`, `pkg/storage`,
`pkg/transport/*`, and `pkg/kvsm` are unchanged in behaviour (the model is a
semantic mirror of kvsm, not a runtime consumer). No RFC is owed. The phase
branch `feature/linearizability` (PROC-07) and Conventional Commits (PROC-08)
are enforced at commit time by the executor/orchestrator.

## What surprised us

- **The recorded chaos dumps were trivially linearizable.** The Phase-11
  histories are single-client (`ClientID=0`) and non-overlapping, so Porcupine
  returns `Ok` on them even if Raft were broken (matrix_test.go:200-206). This
  forced Option A: hand-authored concurrent multi-client histories are the only
  way to build a gate that actually bites, since Porcupine has no leader concept
  and "churn" must be modeled as later ops from distinct `ClientId`s.
- **The fault-injection test passes because the history is illegal.** SC4
  exercises the violation path without ever breaking `pkg/raft` — the crafted
  lost-committed-write history returns `Illegal` and produces the visualization,
  and that *is* the passing assertion (mirrors porcupine's own
  `visualization_test.go`).
